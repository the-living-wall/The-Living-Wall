# SDK 契约与发布候选补验

2026-09-24，北京时间。Refs #88 / Draft PR #91。源 b0de813，后台 SDK 实现 d916ba6；本轮不改应用代码、云端权限或生产部署。

## 实际通过

通过 Chrome 的真实 Web SDK 3.10.1、GATEWAY、现有匿名会话调用 xiaoying-gifts-sdk-probe。12 项检查通过，14 次真实云端调用见 [结果](contract-result.json)：创建重试同 ID、并发认领仅一方成功、认领重试、邀请及无关凭证不能读、actor 从凭证确定、留言重试不重复、同 op 不同正文拒绝、并发版本仅一方成功、冲突不改状态及期限、接收者不能删除。

这里的“响应丢失重试”只证明相同请求在云端可安全重放：探针收到首次响应后再次发送同一请求，并没有制造真实网络超时。因此不把这项写成实际断网/超时界面验收通过。新合成记录按原七天期限清理，不触碰用户刚验收的心意。

16 项相关本地单元测试通过（gifts-transport、gifts-cloudbase），见 local-tests.log；这些与上述真实云端结果分别记录。规格严格校验 10/10，已有 creature-audio 归档提示仍保留。

## 限流失败证据与容量限制

第一轮 4 并发、最多 144 次无效路径读取，在 59 秒内跨了两个固定分钟窗口，144 次均 404，没有取得 429 证据，见 rate-first.json。

第二轮对齐分钟但采用 6 并发，144 次中 108 次为预期无效路径 404，36 次为共享配额文档事务争用 409，未到达计数上限，见 rate-second.json。未改阈值、未绕过限流、未以放慢后正常为限流成功证据。现有每分钟 120 次为全站共享测试上限；两个可见页面每 3 秒轮询约消耗 40 次/分钟（不含写入与重试），不能作为公开发布容量承诺。

第三轮恢复 4 并发并对齐新分钟，但请求延迟使总耗时达到约 77 秒，144 次均 404，仍跨窗口且无 429；见 rate-third.json。停止重复加压，限流触发和恢复保持未通过。三轮共 432 次探针调用，未写入心意；第二轮含 36 次计数事务冲突。

## 正式来源候选准备

已用现有 SDK 前端、PREVIEW_BASE=/friends/ 构建静态候选，输出 outputs/gifts/formal-candidate/friends，见 friends-build.log。此项仅证明子路径构建可生成，不代表已接入主站导航或最终托管路由已验证。

后续可将朋友入口放在现有域名 /friends/，保留个人主页；需要实际集成导航和静态发布产物、安全响应头、最终邀请直达。待产物及回退完整验证后，才申请将 thelivingwall.cn 加入 SDK 安全来源；不增加域名 wildcard、OPA 或收费资源。当前只允许既有本地来源，未改正式域名。

发布仍受共享限流容量、最终来源首访/错误恢复、平台备份与响应日志保留、费用设置、依赖合入与最终 CI 门禁约束。4.3 暂不勾选，3.2～3.4 保留未完成。归档探针源码为 .mjs.txt，不随生产构建发布。
