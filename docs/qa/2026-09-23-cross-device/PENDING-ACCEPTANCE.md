### QA-02 两台真机的共同塑造完整流程

- [ ] 两个独立身份依次验证提议、改选重新确认、拒绝、撤回、恢复表现及取消纪念，双方刷新后核对一致。
- [ ] 单方不能使共同选择生效；取消纪念不删原对话、不自动撤销形态；改名不改历史署名快照。
- [ ] 共同约定只保存纪念，不推断线下履约；多次留言/抚摸不自动改变共同性情。
- 负责人：Codex 提供用例，用户与另一台设备配合。状态逻辑和部分云接口已有覆盖，缺的是完整真机体验记录，不将本机切换身份当作两台设备。

### QA-03 云函数冷启动或实例切换后的恢复

- [ ] 用虚构内容创建、回复并共同确认，记录测试版本；通过可核实的冷启动或实例更替后，在原浏览器验证可读、可继续回复且无重复写入。
- 负责人：Codex。通过条件：保存内容和版本仍一致，凭证仍有效，后台切换有证据。现有浏览器刷新和本地 SQLite 重启不能替代此项。

### QA-04 到期清理的时间边界

- [ ] 使用完整、合法的虚构测试记录，记录到期时刻、访问拒绝时刻与实际删除时刻，覆盖定时器周期边界。
- 负责人：Codex。通过条件：到期即不可读，并验证规格约定的一分钟内活动库清理。此前探针只证明自动清理发生过，未证明最坏延迟；若平台不能满足，先记录差异再由用户决定规格调整。

### QA-05 真实客户端越权与后台入口隔离

- [ ] 通过环境实际支持的未授权客户端路径验证两个集合直接读取、写入被拒，清理函数不能从客户端直接调用。
- [ ] 核对无凭证、错误/跨心意凭证、接收者删除等拒绝路径与最终部署配置一致，错误不泄露消息或管理凭证。
- 负责人：Codex。已有 API 权限测试和配置回读，缺真实客户端直连证据。不得为测试扩大权限或临时开启公开读写。

### QA-06 静态页面与入口安全响应

- [ ] 在最终发布来源验证静态页和 API 的缓存、引用来源及内容类型保护，确认邀请凭证不会进入无关请求或日志。

### QA-07 首次邀请直接进入（已知失败后的待验证）
