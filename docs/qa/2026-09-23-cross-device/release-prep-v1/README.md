## 发布入口核对与建议

当前 `npm run build` 生成个人陪伴 `/` 和 `/showcase`；朋友互动由 `npm run build:gifts` 独立生成，后台另为 CloudBase 云函数。仅合并三张 PR 不会自动把朋友功能接到正式首页。

建议首发沿用已验证的独立朋友服务，绑定独立正式子域名，再从主站提供“送给朋友”入口。个人成长仍只存本机，避免用测试原型首页替换个人陪伴页。具体域名、主站平台的 Git 自动发布配置、HTTPS 和 /api 同源路由仍需核实；本轮没有修改 DNS、网关、账号费用或发布生产。

正式切换依次处理：

1. 打通最终域名首访完整邀请，补静态安全响应头；验证微信首次打开和第三人不能认领已接受邀请。默认腾讯域名的“先开首页”仍只是测试绕行。
2. 补真实客户端权限、冷启动/实例切换、清理延迟和限流恢复验证，明确平台备份保留及费用设置。只操作合成记录，不以本轮本地结果代替云端结果。
3. 按 #70 → #77 → #91 处理依赖与 base，合入前确认最新 CI/审查及主线变化；不得提前删除底座或让合并自动关闭仍有上线事项的 Issue。候选已同步 main 不表示下层 PR 已合并。
4. 在确定的正式来源部署已合入 main 的版本，补主站入口，做定向冒烟与回退演练；记录实际前后端 SHA、域名、产物和回退地址，再确认正式发布完成。

独立测试站仍为前端 `6e148f1`、后台 `7e30d0b`，本轮未更新部署。旧站入口与既有数据不变。回退不能恢复删除或到期数据。
