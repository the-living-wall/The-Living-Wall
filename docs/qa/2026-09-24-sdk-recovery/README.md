# 真实 SDK 响应丢失与草稿恢复

Refs #88 / PR #91，2026-09-24，操作者 Codex。基于 07f61e1 后的修复候选，目标仍为现有 SDK 探针 3abddff。云端权限及生产配置未变。

## 方法与实际结果

Chrome 暂不可用后，使用 Codex 内置浏览器运行仅本机的恢复验收页。构建插件只在 QA 产物中包装官方 client.invoke，生产构建不包含故障注入：

- “发出前失败”：下一次 POST 在调用后台前报网络错误。
- “保存后丢失响应”：等待真实 SDK 返回业务成功，再丢弃该次响应，让未经修改的 sdkTransport 走原 12 秒超时。GET 仍为真实后台读取；不使用假数据库，也不通过浏览器 evaluate 注入网络行为。
- 仅使用虚构内容，测试心意 bb83c75c0f3bb153f1a7922df1245157；保留既有七天到期，不修改用户验收心意。

已实际完成：
1. 创建成功响应被丢弃，页面显示“暂未确认保存结果”，保留原文与恢复甲/恢复乙称呼。刷新后重新打开创作仍显示相同内容，重试恢复创建结果。创建幂等唯一性还沿用此前真实 SDK 契约的 ID 对照证据，本次未在丢弃前记录返回 ID，不单独声称完成该 ID 对照。
2. 留言发送前失败，未显示发送成功。发现刷新后原请求虽保留、回复框却显示空白；此为本轮真实缺陷，已修复。刷新后打开回复框能看到“发送前失败：刷新后继续这句虚构留言。”，重试后后台出现一条。
3. 留言后台保存后丢弃响应，原 12 秒超时正常生效。刷新后后台已有一条、原请求仍待确认；回复框恢复“保存后响应丢失：重试不能出现第二条。”。重试完成后对话中该正文数量为 1，待重试按钮数量为 0。
4. 改名发出前失败；刷新后恢复“恢复甲二”，重试成功。
5. 共同提议发出前失败；刷新后引用仍勾选原消息、形态仍为俏皮、理由仍为“待确认提议恢复：虚构理由。”。待确认期间引用和形态禁用，避免界面改成新内容却重发旧请求。重试后出现单一待确认提议，仍等待恢复乙选择，活跃形态保持原样。

脚本存档为 client-source.ts.txt、entry-source.tsx.txt、build-source.mjs.txt；在 outputs/gifts/recovery-harness 下还原文件名后构建，仅在本机提供服务。不得将 QA 页/QA bundle 发布生产；正式产物必须重新构建自仓库入口。

## 修复范围

OnlineApp 向编辑器提供本机待确认 action；编辑器打开时恢复对应的留言、称呼或提议文字/引用/形态/版本，不生成新 operation ID，不自动发送。没有待确认请求时保持原编辑行为；普通未点击发送的草稿不在本次新增跨刷新保证范围内。

另补 SDK 运行入口的脱敏诊断候选：只记录固定事件名、状态码及耗时，意外错误也转成通用 500，不记录请求、平台上下文、响应正文或凭证；新增针对正文/凭证/上下文/异常泄露的单测。此代码还未部署，平台 IgnoreSysLog=false 仍会记录系统响应，必须配置后实测才可宣称日志正文问题解决。不能将本地日志单测等同平台留存验证。

生产来源首访、实际响应头、冷实例浏览器恢复以及费用/备份门禁保持未完成。

本地最终检查：108 项测试通过，typecheck、lint、主站 build、腾讯完整 build、严格规格 10/10 通过。构建顺序串行；日志在本目录。首次 QA 包类型检查因临时测试包装器的 DOM 类型断言失败，修正 QA 包断言后通过；该测试包装器不属于生产代码。
