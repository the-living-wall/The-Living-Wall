# Mac + Gemini 335 + 投影仪：真实硬件启动

适用：Apple Silicon Mac、Orbbec Gemini 335、本机开发前端与投影仪。关联 [#96](https://github.com/the-living-wall/The-Living-Wall/issues/96)、[IN-03 / #50](https://github.com/the-living-wall/The-Living-Wall/issues/50)。2026-09-26 对照 main 的启动脚本、桥接和界面核对：核心步骤与此前本机测试一致，本次只整理文档，没有新增一轮硬件验收。

这是本地近墙区域实验，不是生产站点的硬件功能，也不证明手部识别、真实触碰或精确投影映射。Windows 适配另见 #49，不直接套用本页 Mac 命令。

## 先分清首次安装与日常启动

首次拉取、换电脑或从 Windows 迁移后，按[同伴拉取与前端测试](frontend-checkout.md)安装 Node.js 24、Git，并在自己的项目目录运行 `npm ci`。不要复制其他机器的 `node_modules`、`.venv` 或 `.runtime`。

深度环境首次安装时，在同一个项目根目录执行（需 Python 3.12 ARM64）：

```sh
python3.12 -m venv tools/depth-lab/.venv
tools/depth-lab/.venv/bin/python -m pip install -r tools/depth-lab/requirements.txt
```

SDK 安装失败时参照[深度工具说明](../../tools/depth-lab/README.md)的官方 wheel 说明。已经安装成功、仍在同一个目录工作时，日常启动不必重建虚拟环境或重复安装。新克隆/新 worktree 不会自动带上这些忽略文件，需要单独准备依赖。

下面两个终端都要进入同一份代码的项目根目录（含 `package.json`、`tools/`）。不要混用旧下载目录、历史分支的服务和另一份前端。可分别运行 `pwd`、`git rev-parse --short HEAD` 核对。

## 日常启动：按顺序操作

### 1. 连接并固定硬件

- Gemini 335 用 USB 3 连接 Mac；关闭 Orbbec Viewer 和其他占用相机的软件。
- 投影仪开机，选择接线对应的信号源。在 macOS 显示器设置中确认能看到投影画面：镜像屏幕直接显示主页面；扩展桌面则把前端浏览器窗口移到投影屏幕。
- 先固定相机、投影仪和墙面，选好测试位置。投影出画与深度采集是两条独立链路，两者都需要检查；无线投屏与有线连接也要分别记录。

### 2. 终端 A：启动前端

```sh
npm run dev -- --port 3018
```

保持终端运行，打开 [小莹主页面](http://localhost:3018/)。本页统一使用 3018；根 README 中的 3017 是另一个前端端口示例，不需要两个都开。如果端口被占用或终端显示自动换端口，先按下方排查，不要误连另一份旧前端。

深度入口只存在于开发服务，不能用线上页面、`npm run build` 的产物或双击 HTML 代替。

### 3. 终端 B：启动真实深度服务

此前本机使用的是独立 USB 采集权限脚本。在项目根目录运行：

```sh
zsh tools/depth-lab/启动相机权限测试.command
```

如出现 `Password:`，只在自己的 macOS 系统终端输入管理员密码，输入时不显示字符；不要发到聊天里。脚本仅用管理员权限启动 USB 采集进程，网页服务仍是普通用户权限；不要用 `sudo npm`，也不要给整个网页服务提权。

脚本会打开 [深度测试台](http://127.0.0.1:8769/)。确认出现持续更新的深度画面和“真实相机 · 独立读取”；“独立相机自动连接”按钮变灰是正常的，不需要再点连接。此终端同样保持运行。

若另一台 Mac 已确认普通权限可读取相机，可改为下面的方式，然后在测试台点击“连接 Gemini 335”（两种启动方式二选一）：

```sh
tools/depth-lab/.venv/bin/python tools/depth-lab/server.py --port 8769
```

若出现 `uvc_open -3`，先 Ctrl+C 停掉这个服务，再运行权限脚本。主前端桥接固定读 **8769**；`启动深度测试.command` 默认的 8765 和旧记录中的 8767 都不是本流程的服务地址。

### 4. 校准空墙

1. 在深度画面拖动白色选框，只选平整的空墙/硬板，不包含人、手、家具或墙角。不要把电脑显示器当触摸测试面。
2. 移开手和身体，点击“校准框内空平面”，保持相机与表面不动，等 30 帧采集结束。
3. 确认不再是“等待校准”或“未校准或证据不足”。空墙时出现“区域空闲 / 已离开”、近墙 0 区是正常的，不必为了出现输入而让手留在校准画面里。
4. 若提示“不够平整或观察角度过斜”“有效深度不足”，调整选区/位置后重做，不能只看进度条结束就认定校准成功。

校准只存在于深度服务内存。重启深度服务、断开后重新连接、移动相机/墙面，或更改选框，都需要重新校准。移动投影仪后，本流程也重新检查摆位并重做空墙校准，再检查画面方向；这不等于完成投影四点映射。

### 5. 启用深度输入

回到 [小莹主页面](http://localhost:3018/)，点击“启用深度实验”，不是“启用摄像头”（后者是普通 RGB 手掌识别）。两个输入模式互斥，不需要额外开启电脑摄像头或下载 MediaPipe 模型来运行深度输入。

- 没有物体靠墙时：“空墙 / 等待物体靠近墙面。”是正常待机。
- 手或物体靠近测试区域时：“检测到近墙区域，小莹跟随中（尚未识别手或确认触碰）。”是正常输入提示，不是报错。
- 绿色空心圆表示最大近墙区域的中心，不是手背、指尖或已确认触点。慢慢左右、上下移动，按实际画面调整“左右镜像”“上下镜像”。

日常互动没有“必须在 30 秒内做动作”的限制。只有另行启动“引导测试”时才按页面倒计时操作。

### 6. 检查投影效果，再进入纯画面

先保留控件和绿色光圈，逐项观察：方向跟随、镜像切换、移开手后光圈消失；关闭深度实验后旧输入应清除，鼠标模式可继续使用。专门测断流时，先重新启用深度实验并让物体靠墙，确认有光圈/输入，再在终端 B 按 Ctrl+C，确认旧光圈/输入清除；之后按步骤 3–5 恢复并重新校准。

恢复深度输入后，将主页面放在投影屏幕上，点击“全屏纯画面”；此时控件和绿色光圈会隐藏，不等于断流。按 Esc 或双击画面返回。需要声音时在页面主动开启，并确认 Mac 的音频输出设备。

以墙上的实际方向、跟随和移开手的反应判断体验，不只看电脑屏幕。镜像只能翻转坐标，不能补偿相机与投影仪位置差异；准确墙面映射仍由 #46 跟踪。

## 重启与异常恢复

- **只移动设备，两个页面仍正常：**先关闭深度实验，固定新位置，再执行步骤 4–6；不必重装依赖。只有移动投影仪时也按本流程重检摆位与方向。
- **息屏、拔插设备或切换投影信号源后断流：**先确认 USB 和信号源、关闭占用相机的软件；在原终端 B 按 Ctrl+C 停止旧服务，再执行步骤 3–5。前端正常时不用重启终端 A。页面刷新不会重启采集进程。
- **需要完整重启：**先退出纯画面并关闭深度实验，两个原终端分别 Ctrl+C；从步骤 2 开始。深度服务重启后必须重新校准。
- **仅刷新前端/重启前端：**重新开启深度实验；若深度服务未重启、设备/表面和选区未变化，原空墙校准仍在，不必把刷新页面当作重新校准。
- **独立读取模式点了“断开”：**要恢复时重启权限脚本；灰色“独立相机自动连接”按钮不能用于重连。
- **前端提示无法连接本地深度：**先检查测试台 8769 是否打开且有实时画面，再确认前端是同机 `npm run dev` 的页面。不要改成模拟模式冒充恢复成功；前端会拒绝模拟数据。代理排查应让 `localhost`/`127.0.0.1` 直连，不要随意修改全局代理配置。
- **端口占用：**运行下面的只读命令找监听进程，核对原终端后 Ctrl+C；不要批量杀死其他 Node/Python 服务。

```sh
lsof -nP -iTCP:3018 -sTCP:LISTEN
lsof -nP -iTCP:8769 -sTCP:LISTEN
```

## 记录一次测试

记录代码版本（`git rev-parse --short HEAD`）、Mac/浏览器、相机型号、投影连接方式、校准结果，以及“做了什么 / 预期 / 实际 / 是否可重复”。方向与镜像、移开手、断流、退出模式四项分别写通过/失败/未测，不把普通跟随代替全部验收。

需要数值记录时，在测试台点击“开始引导测试”，按页面步骤完成并下载数值报告；刷新或关闭前下载，未下载记录只在页面内。普通互动不会自动保存测试记录，数值报告也不是录像。有条件可拍手与投影同框的视频辅助判断延迟，但非必需，注意避开个人信息。真实物理触碰、手部识别和毫米级精度仍不能从以上现象推出。
