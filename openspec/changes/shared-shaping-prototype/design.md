# Design

## Context

见 proposal.md。底座 `prototypes/live-gift/Companion.tsx` 保留原站页面、引擎与声音，但只有本页 note/echo 状态。`Creature.care/affection` 来自抚摸，`growthStage` 由成熟度派生，不能拿朋友对话直接加分。原型已把存档改为内存 Map。#70 尚未合并，因此 #76 暂用依赖分支，保留底座体验供对照。

## Goals / Non-Goals

**Goals:** 状态转换可测试；性情试看与共同结果隔离；用户可用两个明确标记的模拟身份走完选择流程；新表现只在原型中组合已有渲染。

**Non-Goals:** 不验证两个真人身份，不提供公开分享或通知，不推断人类人格/关系分数，不自动生成对白，不改变成长存档版本。

## Decisions

- **独立状态模块与一项待确认提议。** 留言、纪念、已生效方案及历史存于 React 内存。以单调递增的提议版本约束确认/拒绝/撤回；改选使所有旧同意失效。避免分散布尔值导致切换视角即误确认；多项并发提议留到真实服务设计时处理。
- **片段快照而非动态引用。** 用户手动勾选已有留言，说明可留白，留言和说明沿用 80 字限制。来源记录保留当时文字与模拟作者，后续新留言不会改写既有来由。空白输入不创建事件。
- **历史改选沿用快照。** UI 与提交处理共用来源解析：修改待确认提议时优先保留该版本的片段，再追加后来留言。同编号的现有赠言不得替换历史原文；过期版本仍由提议版本检查拒绝。
- **两条共用的确认路径。** 记忆与性情提议共用版本/双方确认规则。取消纪念与恢复历史性情也是提议；界面使用「取消纪念」，不宣称删除了原对话。只保留已生效变更的可读历史，不用未同意记录评价参与者。
- **固定表现目录。** `calm/v1`、`playful/v1`、`curious/v1` 是初始三套。共同状态存完整版本键，渲染按此键读取，不用“最新版本”动态替代。`original/v1` 表示原样，可用于恢复。
- **展示适配层。** 在现有绘制之后增加有限幅度的光纹/探光与轻微动作，保留身体位置与基础触摸计算；不修改 `Creature`。实时读取休息、受惊与恢复状态，减少动态偏好时静态呈现。表现只在朋友视角可见，取消/切换清除试看。目录文字准确描述实际首版效果，不称完成全部性格行为。
- **沿用现有阅读列与操作区。** 来回留言沿原左侧区域按需展开；来源选择和方案预览按需打开编辑层，避免常驻大卡片。右上当前状态与底部声音不改用新的状态分数。身份切换明确写“体验身份”；本页保存动作使用演示措辞。
- **收到提议的试看单独呈现。** 和编辑中的试看复用紧凑视图，但返回目标为原提议；关闭不修改提议或同意记录，取消纪念的确认按钮明确使用“取消”文案。
- **已有服务保持不动。** 原型以独立端口 4180 运行，不接 API、不增加依赖、不读取成长 localStorage。修改目录限定为原型、新测试、测试入口及产品文档。

## Risks / Trade-offs

- [本机切换可由一个人操作] → 持续显示同机演示；测试证明的是角色状态约束，不是真人认证。
- [三种表现过于接近] → 浏览器逐一预览与留证，最终可辨识性由用户体验验收；不靠文案宣称成功。
- [对话变长挤占空间] → 默认显示最近来回，历史展开阅读；长内容自然滚动，手机编辑层限高。
- [新光感盖住原有身体] → 小幅、有限透明度，并在休息/受惊时停用；保留原引擎数值对照测试。
- [依赖 PR 和主线演进] → 不改生产文件；#70 合入后同步 main、改 PR base 并重新验证。未经验收不合并或部署。

## Migration Plan

无数据迁移。浏览器刷新清空演示数据；删除原型变更或回到 4179 即可回看上一版。真实持久化、恢复凭证与通知未来另立规格。
