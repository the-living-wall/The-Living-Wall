# Spec Delta

## Purpose

为本机深度互动提供可测量且不会持续积压旧帧的位置输入，区分采集后软件耗时、显示传输与光团自身动画；保持既有近墙检测语义与隐私边界，明确现场设备验收不能由软件模拟替代。

## ADDED Requirements

### Requirement: 轻量且可追溯的输入
系统 SHALL 提供无图片和轮廓的本机只读输入，包含会话、唯一递增帧号、SDK接收后帧龄和处理耗时；旧测试台接口保持兼容。新网页 SHALL 拒绝不支持的新协议并提示更新。

#### Scenario: 新旧服务
- **WHEN** 网页连接新版或旧版深度服务
- **THEN** 新版返回可追溯位置，旧版明确提示更新，不回退旧数据。

### Requirement: 有界更新与新鲜度
系统 SHALL 以33ms目标周期单请求取点，不补发积压请求；仅新鲜新帧更新输入。重复/乱序帧不延长有效期；无效、无区域或校准中立即清除，超过300ms无新鲜有效帧时清除，正常前台浏览器清除不晚于350ms。

#### Scenario: 重复帧与断流
- **WHEN** 上游重复返回旧帧或停止响应
- **THEN** 旧位置不能继续触发互动，并在时限内清除。

#### Scenario: 重启与退出
- **WHEN** 服务重新启动或用户退出深度模式
- **THEN** 新会话可从低帧号重新开始；退出后的迟到响应不恢复输入。

### Requirement: 最新帧处理
采集与处理 SHALL 解耦，待处理槽只保留最新一帧，记录覆盖数量；预览独立最高10Hz，不阻塞输入快照。校准 SHALL 计入30张不同的新帧。

#### Scenario: 慢处理
- **WHEN** 检测或预览慢于采集
- **THEN** 队列不持续增长，处理跳到最新帧，校准不重复计数。

### Requirement: 数值诊断与验收边界
诊断 SHALL 只按用户启动记录和导出数值，区分唯一帧率、处理时间、请求往返、显示更新间隔、掉点与SDK接收后显示提交保守估计；不自动录制原始图像。软件30fps输入目标为至少25唯一帧/s、保守P95不超过100ms；有线动作到标记P95目标150ms必须独立现场验证。

#### Scenario: 软件与现场对照
- **WHEN** 导出基线或优化报告
- **THEN** 标明代码、环境、输入类型和测量边界；未接硬件不宣称硬件目标通过。

### Requirement: 保留产品与访问边界
系统 SHALL 保留现有近墙50mm规则、镜像、模拟拒绝、存档隔离和行为参数；输入接口仍仅限本机同源开发，生产无该接口。

#### Scenario: 无效来源
- **WHEN** 模拟、未校准、跨域或非本机输入请求到达
- **THEN** 不生成有效互动，不开放额外访问范围。
