# Design

## Context

原代码为 bffc5a1，深度主前端请求后等待100ms；代理先接收含JPEG的状态再丢图片。服务检测与编码共锁，frame_at在检测完成时计时。动机见proposal，现场回退保留完整旧提交。

## Goals / Non-Goals

采用既有本机HTTP与Python线程，不引入WebSocket或额外依赖。不调整采集分辨率、近墙几何/行为参数，不用软件模拟替代有线或AirPlay测量。

## Decisions

- `/api/input` 协议版本1，提供 stream_id/frame_id/source_age_ms/processing_ms 与裁剪后的有效性/中心/面积；`/api/state`保持诊断兼容。桥接白名单转发，不允许上游图片或轮廓泄漏。
- 采集进程在收到SDK帧后立即记录同机Python monotonic时间，随长度定界管道帧传递。SDK设备时间只作诊断，不与JS performance.now相减；新网页按source_age + 本次完整RTT保守估计新鲜度。
- 采集、管道排空、检测与预览分离，各交接使用单槽覆盖最新值；不丢半个管道消息。状态短锁发布不可变快照；校准/检测另用锁和代际号防止重置后的旧结果复活。预览线程最高10Hz。
- 可测试的客户端轮询器承载33ms起点周期、单请求、会话/帧号去重和独立新鲜度看门狗；React只负责回调和诊断界面。重复帧不调用sample，超时不叠加重试。
- 显式诊断模式保留有限的数值样本并下载JSON；浏览器rAF/布局提交估计不等于物理发光时间。基线/优化均使用实际浏览器和相同30fps合成上游，另列硬件未完成项。

## Risks / Trade-offs

- SDK内部缓存不可测 → 记录设备时间/帧号与实际帧率，source_age明确从SDK交付开始。
- 新旧管道不兼容 → 明确协议错误，要求同时重启采集和服务，不伪造新鲜度。
- 丢旧帧减少完整序列 → 本任务实时互动优先；校准仍收集30张独立新帧。
- 用户已确认相机为 Gemini 335，与当前适配一致；有线现场延迟仍待验收，连接时记录 SDK 枚举信息与流配置。
