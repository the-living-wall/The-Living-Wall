# Design

## Context
见 proposal.md。生产提交 4c81919，部署 dpuoitv6jpf0。此次由现有 main 派生独立分支。

## Goals / Non-Goals
保持凭据、创建幂等、共同确认和成长存档逻辑不变；新增一个版本化引导标志。无后端改造。

## Decisions
- 使用同一个声音组件供主页与朋友页使用，避免复制的错误再次分叉；保留朋友接收页手动启音策略。
- 音效和音乐分别报告就绪；任一播放即可关闭声音，部分失败给出明确重试，生命周期恢复尊重关闭意图。
- 桌面左侧内部滚动，右下工具区锚定视口；小莹画布仍覆盖全屏，不改运动/输入。手机保留文档滚动，工具栏固定底部，按工具栏实际高度为内容留空；摄像头、重置和全屏收进互动设置。保存说明以有高度限制的浮层展开，避免改变页面高度。两业务区持续呈现，待共同提议不折叠。
- 缩小开场标题和间距、紧凑分享/管理，按钮改“共同选择”。保存文案说明七天、原浏览器找回及备份延后清理，数据规则不变。
- 引导两秒后淡出，悬停/聚焦暂停；玩法说明可长期展开，弱动画偏好关闭淡出。存储失败仍可使用。
- 创建异常只简化展示，不更改原请求和重试行为；首次超时限定三十分钟只读排查，缺少日志则如实记录。

## Risks / Trade-offs
- 微信音频策略无法由桌面模拟证明 → 自动化覆盖四种结果及生命周期，另由用户验收 Android 微信。
- 短引导可能来不及阅读 → 保留区标题和不计时的玩法说明。

## Migration Plan
检查通过后提供一次集中预览和 Draft PR；用户验收后合并，由现有 EdgeOne 配置发布新 main 提交。回退部署 dpuoitv6jpf0；不清理浏览器数据。
