# Design

## Context

主页面 app/page.tsx 汇总鼠标和 HandCamera 输入后调用 Creature.step；渲染器独立。相机服务在127.0.0.1:8769，Host/Origin检查禁止直接跨域访问。entity.html 已有近墙输入实验但使用不同视觉。当前在独立 Git 工作副本实施；Issue #50 管理本次主前端深度实验，Issue #25 仅涵盖独立测试台。

## Goals / Non-Goals

Goals: 在原版画面完成本机深度联调，保留失效门控、原版反应及存档兼容。
Non-Goals: 手部语义模型、精确触碰、投影单应性校准、生产发布。

## Decisions

- Vite configureServer 中提供固定的只读开发路由，仅访问127.0.0.1:8769/api/state，去除image后响应；检查本地Host和同源请求，不接受可变目标或路径。比开放相机CORS范围更小，不需要重启管理员采集进程。
- 纯适配函数验证输入、选择最大near_regions区域。客户端约每100毫秒轮询，超时与独立新鲜度检查清除输入；仅真实camera/pipe模式允许互动，拒绝simulation。
- 页面显式开启后挂载组件；输入互斥、镜像、可见位置指示；校准链接回现有测试台，不通过新代理转发写入。
- 近墙区域作为实验性互动门控，让用户测试现有抚摸视觉；独立localStorage键隔离实验成长。原版画面仍遵循行为模型，不承诺光体中心刚性贴随手。
- 提示优先级为连接错误、校准中、未校准、无效原因、等待区域、有效区域；避免entity页校准时的误导文案。

## Risks / Trade-offs

- [身体可能抢占最大区域] → 明确几何区域边界，现场检验，暂不承诺手部识别。
- [延迟与坐标映射] → 300毫秒门控、镜像和位置指示；投影精确映射另做验收。
- [平台代理兼容] → 验证Vinext开发路由可达，生产构建不包含开发接口。
- [本地工作区差异] → 从最新 main 的独立克隆实施，保留 102 根目录及旧下载副本的已有改动。

## Migration Plan

2026-09-20 可复现交付补充：用户要求同伴拉取即可测试。将 #25 提交 bd167a1 中与现场临时副本一致的服务子集纳入 tools/depth-lab，普通前端只安装 npm 依赖，相机联调另建 Python 3.12 环境。权限脚本统一 8769，不依赖个人目录。此为依赖补齐，不合并 #52 的后续手部诊断功能；后续处理重叠文件时保留上游新增功能。

本地开发验证后交用户现场验收。切换回普通模式即可退出实验；代码通过独立分支/PR维护，不直接修改线上部署。没有现场结果时不关闭验收Issue。
